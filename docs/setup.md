# Setup: Supabase, Render and Google sign-in

All three are free and need no credit card. Do them in this order. Total time: about 30 minutes.

Throughout, replace `offerboard.onrender.com` with your real Render URL if that name is taken
(Render shows the URL on the service page).

---

## 1. Supabase (the database)

1. Go to <https://supabase.com> and sign in with GitHub.
2. **New project**
   - Name: `offerboard`
   - Database password: click **Generate a password**, then copy it somewhere safe (a password
     manager). You can't see it again.
   - Region: **East US (Ohio)**. Render's server is also in Ohio, so every query stays in the same region and is fast.
   - Plan: Free.
3. Wait a minute or two for it to finish provisioning.
4. **Turn off the Data API.** Supabase normally exposes every table through a public REST API.
   Offerboard only talks to the database through Django, so switch that off:
   **Project Settings → Data API → turn off "Enable Data API"** (wording may vary slightly; it is
   the setting that controls the auto-generated REST API). This also clears the
   "RLS disabled" warnings in Supabase's Security Advisor.
5. **Get the connection string.** Click **Connect** (top of the project page) → **Connection
   string** → **Method: Session pooler**. Copy the URI. It looks like:

   ```
   postgresql://postgres.abcdefghijkl:[YOUR-PASSWORD]@aws-0-us-east-2.pooler.supabase.com:5432/postgres
   ```

   Replace `[YOUR-PASSWORD]` with the password from step 2. If the password contains symbols like
   `@ / : ? #`, they must be URL-encoded. It's easier to reset the password (Project Settings →
   Database) to one with only letters and numbers.

   *Why the session pooler and not the direct connection?* Supabase's direct connection is
   IPv6-only, and neither Render nor GitHub Actions can reliably reach IPv6 addresses. The session
   pooler is IPv4 and behaves like a normal Postgres connection.

6. **Test it from your laptop:** put the URI in `.env` as `DATABASE_URL=...`, then run
   `python manage.py migrate`. You should see the tables appear in Supabase's **Table Editor**.
7. **Create your admin account** (Render's free tier has no shell, so do it from your laptop
   while `.env` points at Supabase):

   ```
   python manage.py createsuperuser
   ```

   Afterwards, remove `DATABASE_URL` from `.env` (or comment it out) if you want local
   development to go back to your local database.

> Free-tier note: Supabase pauses a project after 7 days with no database activity. The daily
> reminder job (milestone 5) touches the database every day, which keeps it awake. Until then,
> if it pauses, click **Restore** in the Supabase dashboard.

## 2. Render (the web server)

1. Go to <https://render.com> and sign up with GitHub. Free web services need no card.
2. **New → Blueprint** → connect your GitHub account if asked → pick the `offerboard` repo.
   Render reads `render.yaml` from the repo and shows one web service called `offerboard`.
3. It asks for the variables marked `sync: false`:
   - `DATABASE_URL`: the Supabase session pooler URI from step 1.5.
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`: leave empty for now and fill them in after section 3.
   `SECRET_KEY` is generated by Render automatically.
4. Click **Apply**. The first build takes a few minutes. It installs packages, builds the CSS,
   collects static files and runs migrations (see `build.sh`).
5. Open the URL shown at the top of the service page. Sign up, sign out, sign in.
6. Visit `/admin/` and sign in with the superuser you created in step 1.7.

Every push to `main` now deploys automatically.

> Free-tier note: the service sleeps after 15 minutes without traffic. The first visit after that
> takes roughly 30–60 seconds while Render starts it again; after that it's fast. The app itself
> boots in well under a second; the rest of the wait is Render starting the server.

## 3. Google sign-in

1. Go to <https://console.cloud.google.com>. No billing account is needed for sign-in.
2. Top bar → project picker → **New project** → name `Offerboard` → **Create**, then select it.
3. Menu → **APIs & Services → OAuth consent screen** (also called **Google Auth Platform**) →
   **Get started**:
   - App name: `Offerboard`; user support email: your email.
   - Audience: **External**.
   - Contact email: your email. Accept the policy → **Create**.
4. **Clients → Create client**:
   - Application type: **Web application**, name `Offerboard web`.
   - **Authorized JavaScript origins**:
     - `http://localhost:8000`
     - `https://offerboard.onrender.com`
   - **Authorized redirect URIs** (the trailing slash matters):
     - `http://localhost:8000/accounts/google/login/callback/`
     - `https://offerboard.onrender.com/accounts/google/login/callback/`
   - **Create**, then copy the **Client ID** and **Client secret**.
5. **Audience → Publish app** (status becomes *In production*). While the app is in *Testing*,
   only Google accounts you list as test users can sign in. Offerboard asks only for your name
   and email (`profile`, `email`), which Google doesn't require a review for, so publishing is
   immediate.
6. Add the two values:
   - Render → your service → **Environment** → set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`
     → **Save changes** (Render redeploys).
   - Your local `.env`, if you want Google sign-in while developing.
7. The sign-in page now shows **Continue with Google**.

If Google shows `redirect_uri_mismatch`, the redirect URI in step 4 doesn't exactly match the
URL in the error message (check `http` vs `https` and the trailing slash).
